<StepCard num="CMP-01" label="核心">
  <SectionHead line1="框架为什么存在" line2="高效稳定的工程化催生出来的" />
  <Note tag="本质">
    所有代码的本质，都是为了<strong>高效、稳定的工程化</strong>——让人能更快把东西做出来、做稳，还能多人协作、长期维护。规模一大，光靠「三件套 + 原生 JS」从头手写就太累了，于是<strong>框架应运而生</strong>。
  </Note>
  <Note tag="智慧">
    框架的本质就两件事：<strong>快速解决问题</strong>，以及<strong>积累前人的智慧</strong>。它把无数人踩过的坑、总结出来的最佳实践，沉淀成默认行为和现成的轮子——你不必重新发明一切，站在前人肩膀上往下走就行。
  </Note>
  <Note tag="组件化">
    而前端框架最本质的一件事，是<strong>组件化</strong>——把页面拆成一块块独立的小积木，<strong>像搭积木一样拼出整页</strong>。到了 <strong>AI 时代</strong>，这一点被彻底放大：你不必亲手砌每一块积木，<strong>只需描述「我要什么组件、它该干什么」</strong>，剩下的交给 AI。所以认得组件、说清组件，比会写组件更重要——这正是这门课的重心。
  </Note>
  <Note tag="本节">
    本节先认框架（具体就是 <strong>React + TypeScript</strong>），再认它拆出来的<strong>基础组件</strong>——按钮、卡片这些 UI 词汇。
  </Note>
</StepCard>

<StepCard num="CMP-04" label="组件">
  <SectionHead line1="先认基础组件" line2="界面最小的可复用零件" />
  <Note tag="承接">
    React 把界面拆成一个个<strong>组件</strong>——这一节就认最基础的那几个：按钮、输入框、卡片这类能嵌进任何页面的小零件，是 UI 的「词汇表」。每个组件答三件事：是什么、怎么用、怎么一句话告诉 AI。
  </Note>
  <Note tag="范围">
    本节<strong>只详讲一个最典型的组件</strong>（Card），其余常用组件用一张速查表带过。区块级组件（Hero 主视觉、Navbar 顶栏、Sidebar 侧栏）体积大、管整页骨架，放到进阶篇。
  </Note>
</StepCard>
