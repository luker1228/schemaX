<StepCard num="BOX-01" label="核心">
  <SectionHead line1="先记住这一句" line2="页面 = 一层层套盒" />
  <Note tag="核心">
    在 CSS 的眼睛里，按钮、卡片、标题……每个元素都是一个<strong>盒子（box）</strong>。
    盒子从里到外四层：
    <strong>内容 content</strong> →
    <strong>内边距 padding</strong> →
    <strong>边框 border</strong> →
    <strong>外边距 margin</strong>。
    改「松紧、描边、和邻居的距离」，改的就是这几层——不是另起一套宇宙。
  </Note>
</StepCard>

<StepCard num="BOX-04" label="扩展">
  <StepSplit wide>
    <SectionHead line1="盒子有父亲" line2="CSS 会继承" />
    <Note tag="扩展">
      页面不是一堆平铺的盒子，而是<strong>套娃</strong>：大框里还有小框。
      在 HTML 树里，这叫<strong>父子</strong>；在 CSS 里，有些属性会从父亲<strong>传给</strong>孩子——叫<strong>继承（inheritance）</strong>。
    </Note>
    <p class="m-0 text-base leading-relaxed">
      {
        '直觉：Figma 里父 Frame 改了字色，里面的 Text 常跟着变；但父 Frame 的 Padding，'
      }
      <strong>{'不会'}</strong>
      {
        '变成每个子层自己的 Padding。CSS 也一样——会传的、不会传的，要分清。'
      }
    </p>
    <DocTable label="常见：会传 vs 不传">
      <thead>
        <tr>
          <th>类别</th>
          <th>例子</th>
          <th>记法</th>
        </tr>
      </thead>
      <tbody>
        <tr>
          <td class="doc-props__name">会继承</td>
          <td>
            <code>color</code> · <code>font-*</code> · <code>line-height</code>
          </td>
          <td class="doc-props__desc">「文字怎么长」——顺着树往下淌</td>
        </tr>
        <tr>
          <td class="doc-props__name">不继承</td>
          <td>
            <code>padding</code> · <code>margin</code> · <code>border</code> ·
            <code>background</code> · <code>width</code>
          </td>
          <td class="doc-props__desc">「盒子自己的壳」——只贴在自己身上</td>
        </tr>
      </tbody>
    </DocTable>
    <Note tag="别混">
      <strong>继承</strong> ≠ 子元素「住在父亲里面」。
      嵌套（父子树）永远在；继承只决定：某些属性值要不要自动抄父亲的。
      需要强制抄时，才写 <code>inherit</code>；需要掐断时，在子元素上自己写覆盖值。
    </Note>
